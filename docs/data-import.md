# 下载与导入操作

## Web 操作

启动系统后，在“历史台风数据”或“系统设置”的 IBTrACS 数据源管理区执行：

1. 选择官方数据下载，创建后台任务。页面展示已下载字节数、速度、任务阶段以及服务器可提供时的总大小和百分比。
2. 下载成功并通过文件格式校验后，后台继续解析和入库。HTTP 请求不会等待完整下载与入库结束。
3. 查看任务记录、导入统计或失败原因。刷新页面后仍可查询已保存的任务。
4. 若网络无法访问 NOAA，可上传手动获取的真实 CSV；系统流式接收文件并交给后台导入，不在浏览器一次性解析整个文件。

下载或导入期间可使用取消操作。取消会停止任务；未完成下载保留可恢复的临时内容，入库取消不会保留半个正式数据集。取消生效可能要等当前网络读取超时或解析批次结束。

相同数据源使用单后台工作任务，防止重复任务并发写入。重复文件按 SHA-256 检测；重新导入不会造成台风事件或观测数据翻倍。源文件和任务日志仍可用于追溯。

## 命令行

在项目根目录、使用项目虚拟环境执行：

```powershell
.\.venv\Scripts\python.exe -m backend.cli download
.\.venv\Scripts\python.exe -m backend.cli import "D:\气象资料\ibtracs.WP.list.v04r01.csv"
```

命令行与 Web 入口复用相同的解析、清洗、登记和入库规则。输入路径应指向真实 IBTrACS CSV，不能传入其他格式文件后仅修改扩展名。可使用 `--help` 查看当前命令可用参数。

## 文件和任务状态

- 原始档案：`data/raw/ibtracs/`；保留未修改的完整 CSV 与 SHA-256 元信息。
- 下载临时内容：正式确认成功前使用临时文件；不会把未完成文件报告为可用数据。
- 数据库：默认 `data/system.db`，可通过根目录 `.env` 的 `DATABASE_URL` 配置。
- 日志：`logs/backend.log`、`logs/backend-console.log` 和 `logs/frontend-console.log`。

后台任务记录 `queued`、`downloading`、`importing`、`succeeded`、`failed`、`cancelled` 或重启后的 `interrupted` 状态，保存开始/结束时间、计数和错误。以任务返回的真实状态和清洗统计为准。

## 断点、重试与缓存

下载器使用流式读取、超时和有上限的失败重试。只有服务器正确响应 HTTP Range 并匹配文件条件时才继续已有部分内容；服务器忽略 Range 时重新下载。若无法获知 Content-Length，界面仅显示已下载数据量和速度，不显示虚假的完成百分比。

下载前检查可用磁盘空间。失败时应先查看具体错误（网络、磁盘、格式或数据库），修复后重新创建任务；已有合法文件可复用，临时文件在允许时续传。数据目录、虚拟环境、数据库和大文件均已排除在 Git 跟踪之外。

## 导入报告

每次成功导入记录文件名、版本、字节数、SHA-256、获取/导入时间、原始行数、单位行、研究范围筛选、有效观测、缺失 CMA 风速、无效行、重复/冲突以及真实耗时。研究范围为 2014—2025 年、UTC 时间不跨入 2026 年、观测点 BASIN=WP。所有机构字段分别保存，不进行未来值填充或跨机构隐式合并。

## 常见问题

- 下载失败：保留失败原因，检查官方地址、网络与磁盘；仍可上传真实 CSV。
- 任务在重启后中断：查询任务记录，再次执行下载或导入。不要把旧的运行中状态当作仍在处理。
- 找不到台风：检查年份、名称/编号条件及当前仅导入 WP 观测段的筛选规则。
- 曲线断开：原始缺测或 CMA 特殊低风速代码造成的空值属于正常质量信息；查看观测表和源文件。
- CMA 独立数据源仍显示未接入：IBTrACS 内存在 CMA 字段不等于已导入独立 CMA TXT 数据。
- 页面底图空白：在线瓦片服务可能不可访问；真实轨迹与坐标仍来自本地数据库。
